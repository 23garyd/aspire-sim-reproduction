# Skill index

- [keyframe-geometry-from-trace-images](forbidden-api-workaround/keyframe-geometry-from-trace-images.md) — forbidden-api-workaround: Any time a promising repair stalls on 'I cannot know the object's geometry without reading the asset', AND the trace bundle contains recorded keyframe images (traces/media/seed*_step*_{before,after}.png). Applies across manipulation tasks needing part-level semantics: which end of a tool to grasp, a mug handle's direction, a drawer's pull axis, a peg's long axis. Also apply when re-reading a ledger: a BLOCKED entry is retestable if you can supply a genuinely NEW evidence technique, not merely retry the same reasoning with more confidence.
- [allocate-shared-object-span-between-two-effectors](multi-effector-geometry/allocate-shared-object-span-between-two-effectors.md) — multi-effector-geometry: Whenever two effectors must occupy one object simultaneously and the object's graspable extent is comparable to the required inter-gripper clearance -- i.e. the span is a budget that must be DIVIDED, not a target both arms aim at independently. Apply as soon as a program computes both grasp points from the same perception origin. Also apply when a task brief, baseline comment, or authoring note asserts a minimum buffer/clearance between effectors: treat such a note as a real constraint until disproven, since here it was unconfirmed (task.md had no captured runtime language) yet turned out to be exactly the binding constraint.
